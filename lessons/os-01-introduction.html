Ch1 作業系統導論

來源：00_OS_Syllabus_v1.0.pdf、01_OS_Introduction_v1.0.pdf、期中摘要

學習目標

  • 說明作業系統（Operating System, OS）的角色與目標
  • 比較 Batch、Multiprogramming、Time-sharing 三種系統
  • 會用公式計算 CPU 利用率

直覺說明

把電腦想成一間餐廳。硬體是廚房設備，應用程式是客人的點餐需求，作業系統就是店長：負責分配資源、維持秩序，讓客人不用自己進廚房開瓦斯。

早期電腦沒有 OS，程式設計者必須自己處理檔案、記憶體、除錯與保護。這很耗時，也容易出錯，所以才需要 OS。

核心概念

OS 的三個角色

角色說明
資源抽象（Resource Abstraction）隱藏硬體的複雜度
資源管理者（Resource Manager）管理 CPU、記憶體、I/O
控制者（Controller）控制程式執行，避免錯誤與不當使用

溝通介面：使用者 ↔ OS 是 Shell；應用程式 ↔ OS 是 System Call。

主機系統演進

系統特色缺點／需求
Batch 批次用控制卡（$JOB、$RUN）依序執行工作無互動、CPU 常閒置
Multiprogramming 多道程式多個 Job 放在記憶體，等 I/O 時切給其他 Job需要記憶體管理與 CPU 排程
Time-sharing 分時頻繁切換（Time Quantum），可互動、多使用者需要虛擬記憶體與檔案系統

CPU 利用率

U = C / (C + I)

C 是 CPU 計算時間，I 是 I/O 等待時間。

系統架構

  • SMP：每個處理器執行相同 OS、共享資源。
  • UMA：存取任何記憶體位置的時間相同。NUMA：本地記憶體快，遠端記憶體慢。
  • Hard real-time：錯過期限即失敗（如核電廠）。Soft real-time：逾時可接受（如影音串流）。

程式或範例

printf() 最後會透過 write() 這個 System Call 輸出。下面兩段輸出的效果相同：

#include <stdio.h>
#include <unistd.h>

int main(void) {
    printf("Hello via printf\n");         /* C 函式庫包裝 */
    fflush(stdout);                       /* 先送出緩衝區，確保順序正確 */
    write(1, "Hello via write\n", 16);    /* 直接呼叫 System Call */
    return 0;
}

預期輸出：

Hello via printf
Hello via write

計算範例：C = 2 ms，I = 998 ms。

U = 2 / (2 + 998) = 2 / 1000 = 0.2%

多道程式設計的目的，就是讓不同 Job 的 I/O 與計算重疊，提高這個數字。

考試重點

  • Shell 與 System Call 分別連接哪兩端。
  • Batch、Multiprogramming、Time-sharing 的差異與需求。
  • UMA 與 NUMA 的比較。
  • Hard 與 Soft real-time 的例子。
  • U = C / (C + I) 的計算。

常見錯誤

  • 把 Multiprogramming 和 Time-sharing 混為一談。前者重點是 I/O 重疊，後者重點是互動性（靠 Time Quantum 切換）。
  • 計算 U 時把分母寫成只有 I，漏掉 C。

練習題

題目 1：C = 5 ms、I = 95 ms，CPU 利用率是多少？

U = 5 / (5 + 95) = 5%。

題目 2：為什麼 Batch 系統的 CPU 常閒置？

I/O 速度遠慢於 CPU（至少約 1:1000），且一次只執行一個 Job，等待 I/O 時 CPU 無事可做。

題目 3：Time-sharing 為何需要虛擬記憶體？

多個使用者的程式要同時駐留，實體記憶體不夠，所以需要虛擬記憶體來擴充。
