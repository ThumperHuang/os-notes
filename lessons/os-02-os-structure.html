Ch2 作業系統結構

來源：02_OS_OS Structure_v1.0.pdf、期中摘要（雙模式、開機流程、核心架構）

學習目標

  • 說明 System Call 與 API 的關係，以及參數傳遞的三種方法
  • 解釋雙模式（Dual-Mode）與計時器（Timer）如何保護系統
  • 列出開機流程，並比較單體式核心與微核心

直覺說明

把作業系統想成一棟有警衛的大樓。一般住戶（User Mode）只能待在自己的房間；想使用機房或倉庫（硬體），必須走到櫃檯，填表請警衛（Kernel Mode）代辦。這張表單就是 System Call。

API 則像櫃檯旁貼的「辦事指南」：你照指南填，指南會幫你轉成正確的表單。你不需要知道表單的細節編號，所以同一份指南可以在不同大樓使用（可攜性）。

核心概念

使用者介面（User Interface）

介面說明例子
CLIShell 解析並執行指令；內建指令已載入記憶體，外部指令依 PATH 尋找BASH、KSH、CSH
GUI以圖示與滑鼠操作，1970 年代發明於 Xerox PARCWindows、macOS、GNOME
TUI以觸控手勢操作行動裝置
VUI以語音操作語音助理

System Call 與 API

  • System Call：程式與 OS 之間的介面，透過軟體中斷（Trap）向 Kernel 發出明確請求。
  • API：包裝 System Call 的函式，例如 Windows 的 Win32 API、UNIX／Linux／macOS 的 POSIX API。
  • 例子：C 程式呼叫 printf()，C 函式庫（如 glibc）會攔截並改呼叫 write() 這個 System Call，再把回傳值交還給程式。
類別範例
Process control建立、結束行程；配置與釋放記憶體
File management建立、刪除、開啟、關閉檔案
Device management讀、寫、重新定位裝置
Information maintenance取得時間或日期
Communications傳送、接收訊息

參數傳遞的三種方法

方法做法特色
Registers參數直接放在暫存器最簡單、最快，但暫存器數量有限
Block／Table參數放在記憶體區塊，把區塊位址放在暫存器不限參數數量；Linux 在參數超過 5 個時採用
Stack程式 push 參數，OS 再 pop 取出不限參數數量與長度

Linux 的規則：5 個（含）以下用暫存器，超過 5 個改用 block／table。

雙模式與計時器（Dual-Mode & Timer）

模式Mode bit權限
User Mode1只能存取受限的硬體
Kernel（Privileged）Mode0可執行所有指令、存取所有硬體
  • Privileged instruction 只能在 Kernel Mode 執行，例如 I/O 控制與計時器管理。
  • System Call 會發出 Trap，把 User Mode 切換到 Kernel Mode，完成後再切回來。
  • Timer：OS 設定計數器並遞減，歸零時產生硬體中斷，把控制權還給 OS，避免單一行程霸佔 CPU。

開機流程（Boot Process）

  1. Firmware（BIOS／UEFI）：初始化硬體。
  2. 第二階段 Bootloader（GRUB）：找到核心映像檔並傳入參數。
  3. 核心初始化：核心（vmlinuz）解壓縮並初始化驅動程式與子系統。
  4. 掛載根目錄（Root Mount）。
  5. Systemd／Init：第一個 user-space 行程，啟動各種 daemon。

核心架構

類型說明例子
Monolithic 單體式核心所有 OS 服務都在 Kernel Space 執行Linux
Microkernel 微核心非必要元件移到 User Space（補充）Mach、QNX

程式或範例

用 getpid() 與 syscall(SYS_getpid) 比較「API 包裝」與「直接發出 System Call」，兩者結果相同（需在 Linux 編譯）。

#include <stdio.h>
#include <unistd.h>
#include <sys/syscall.h>

int main(void) {
    pid_t via_api = getpid();                 /* 透過 C 函式庫包裝 */
    pid_t via_syscall = syscall(SYS_getpid);  /* 直接指定 System Call 編號 */

    printf("equal: %s\n", via_api == via_syscall ? "yes" : "no");
    return 0;
}

預期輸出：

equal: yes

用 strace 觀察 System Call：（實際次數依環境而異）

strace -o hello.log ./hello      # 每一行是一個 System Call
strace -c ./hello                # 統計各 System Call 的次數

投影片的示範：C++ 的 Hello World 約 71 個 System Call，Python 的 print('Hello') 約 687 個。一個簡單動作往往需要許多 System Call。

考試重點

  • System Call 與 API 的關係：API 包裝 System Call，例如 printf() → write()。
  • 參數傳遞三種方法，以及 Linux「5 個以內用暫存器」的規則。
  • Mode bit：User Mode = 1、Kernel Mode = 0；哪些屬於 Privileged instruction。
  • Timer 的作用與運作方式（遞減到 0 產生中斷）。
  • 開機五步驟，以及 Monolithic 與 Microkernel 的比較。

常見錯誤

  • 把 printf() 當成 System Call。它是 C 函式庫的函式，最後才呼叫 write()。
  • 記反 Mode bit：User Mode 是 1，Kernel Mode 是 0。
  • 以為 API 與 System Call 一一對應。一個 API 可能呼叫多個 System Call。

練習題

題目 1：為什麼使用者程式不能直接執行 I/O 指令？

I/O 控制是 Privileged instruction，只能在 Kernel Mode 執行。使用者程式必須發出 System Call，由 OS 在 Kernel Mode 代為執行，才能保護系統。

題目 2：某 System Call 需要 7 個參數，Linux 會怎麼傳？

超過 5 個，改用 block／table：把參數放在記憶體區塊，並把區塊位址放在暫存器傳給 Kernel。

題目 3：Timer 如何防止一個行程霸佔 CPU？

OS 先設定計數器並讓它遞減，歸零時硬體發出中斷，控制權回到 OS，OS 就能重新排程。
