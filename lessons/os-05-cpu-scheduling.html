Ch5 CPU 排程

來源：05_OS_CPU Scheduling_v1.0.pdf

學習目標

  • 說明 preemptive 與 non-preemptive 的差別
  • 列出排程指標並計算 waiting time
  • 比較 FCFS、SJF、Round-Robin

直覺說明

排程像銀行叫號。叫號規則再怎麼設計，每位客人辦業務的時間都不會變，能降低的只有「大家在等待區白白坐著的時間」。所以排程只影響等待時間，不影響工作本身要花多久。

核心概念

Preemptive vs Non-preemptive

排程決策可能發生在四種情況：(1) Running → Waiting，(2) Running → Ready，(3) Waiting → Ready，(4) Terminated。

類型排程時機說明
Non-preemptive只在 1、4沒意願才換人
Preemptive1～4 都可能現代 OS 皆採用，但可能造成 race condition，需要同步機制

Dispatcher 負責切換 context、切到 user mode、跳到正確的 PC。Dispatch latency 是停止一個 Process 到啟動另一個的時間。

排程指標

指標意義
CPU utilizationCPU 忙碌比例
Throughput單位時間完成的工作數
Turnaround time從提交到完成的總時間
Waiting time在 ready queue 的總等待時間
Response time從提交到第一次回應的時間
Turnaround = Waiting + Burst（假設不含 I/O）

三種演算法

  • FCFS：先到先服務。簡單，但會有 convoy effect（長工作擋住短工作）。
  • SJF：最短工作優先。平均等待時間最短，但需要預測下一個 burst。
  • Round-Robin（RR）：每人輪流一個 time quantum，適合互動系統。

程式或範例

三個工作同時在時間 0 到達：P1 = 24、P2 = 3、P3 = 3（單位 ms）。

演算法執行順序等待時間（P1, P2, P3）平均
FCFSP1 → P2 → P30, 24, 2717
SJFP2 → P3 → P16, 0, 33
RR（q = 4）P1(0-4) P2(4-7) P3(7-10) P1(10-30)6, 4, 75.67

FCFS 算式：

P1 waiting = 0
P2 waiting = 24
P3 waiting = 24 + 3 = 27
average    = (0 + 24 + 27) / 3 = 17

RR 算式（q = 4）：P1 最後在 30 完成，waiting = 30 - 24 = 6；P2 在 4～7 執行，waiting = 4；P3 在 7～10 執行，waiting = 7；平均 = (6 + 4 + 7) / 3 ≈ 5.67。

用以下 C 程式驗算 FCFS：

#include <stdio.h>

int main(void) {
    int burst[] = {24, 3, 3};
    int n = 3, wait = 0, total = 0;

    for (int i = 0; i < n; i++) {
        printf("P%d waiting = %d\n", i + 1, wait);
        total += wait;
        wait += burst[i];
    }
    printf("average = %.2f\n", (double)total / n);
    return 0;
}

預期輸出：

P1 waiting = 0
P2 waiting = 24
P3 waiting = 27
average = 17.00

考試重點

  • Non-preemptive 只在「Running → Waiting」和「Terminated」時排程。
  • 排程只縮短等待時間，不縮短個別工作的執行時間。
  • SJF 的平均等待時間最佳，但無法事先知道 burst。
  • FCFS 會有 convoy effect。
  • I/O-bound 有大量短 burst，CPU-bound 有少量長 burst。

常見錯誤

  • 把 response time 和 turnaround time 搞混。前者是第一次回應，後者是完成。
  • 算 RR 時忘記 P1 被切走後，還要再排回佇列尾端。

練習題

題目 1：P1 = 6、P2 = 8、P3 = 7，同時到達，用 SJF 求平均等待時間。

順序 P1 → P3 → P2。等待時間 0、6、13，平均 = 19 / 3 ≈ 6.33。

題目 2：為什麼 preemptive 排程可能造成 race condition？

Process 在修改共享資料到一半時被搶走，另一個 Process 讀到不一致的狀態，所以需要同步機制。
