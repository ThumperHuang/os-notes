Ch4 執行緒與並行 Threads & Concurrency

來源：04_OS_ThreadsConcurrency_v1.0.pdf、期中摘要（Amdahl 定律、多執行緒模型、隱含執行緒）

學習目標

  • 說明執行緒（Thread）共享與不共享的資源，以及多執行緒的四大好處
  • 分辨並行（Concurrency）與平行（Parallelism），並會計算 Amdahl 定律
  • 比較三種多執行緒模型與隱含執行緒技術

直覺說明

Process 像一間獨立的廚房，有自己的爐具與食材。Thread 則像同一間廚房裡的多位廚師：共用爐具與食材（記憶體、檔案），但各自有一本進度筆記（PC、暫存器）和一個工作檯（Stack）。

多位廚師共用資源，所以合作快、開新廚師的成本也低；代價是兩人同時搶同一個鍋子時，必須協調（下一章同步的主題）。

核心概念

Thread 共享與不共享

共享（同一 Process 內）不共享（各自擁有）
Code、Data（靜態／全域變數）、OS 資源（如開啟的檔案、signal）Thread ID、Program counter、Register set、Stack

多執行緒的四大好處

好處說明
Responsiveness某部分阻塞或耗時，程式仍可回應使用者
Resource sharing預設共享所屬 Process 的記憶體，比 IPC 容易
Economy建立與切換成本低；Solaris 中建立 Process 約比建立 Thread 慢 30 倍，context switch 約慢 5 倍
Scalability可在多核心上平行執行；單執行緒 Process 只能用一個核心

適合多執行緒的例子：批次產生縮圖、文書編輯器（顯示、輸入、拼字檢查各一個 Thread）、網頁瀏覽器、網路伺服器（one request／thread 比 one request／process 效能佳）。

並行與平行

Concurrency 並行Parallelism 平行
定義多個任務都有進展多個任務同時執行
單核心可以（靠排程器快速切換）不行
多核心可以可以

結論：可以有並行而沒有平行，但有平行就一定有並行。

多核心程式設計的挑戰

  • Identify tasks：找出可平行化的任務
  • Balance：平均分配各核心的工作
  • Data splitting：資料也要切分
  • Data dependency：檢查任務間的資料相依
  • Testing and debugging：平行程式更難除錯

Amdahl 定律（Amdahl's Law）

Speedup ≤ 1 / ( S + (1 - S) / N )

S 是程式中必須循序執行的比例，N 是核心數。當 N 趨近無限大，加速上限為 1 / S。

多執行緒模型

模型對應方式特色
Many-to-One多個 user thread 對一個 kernel thread一個 thread 阻塞，全部都阻塞；無法利用多核心
One-to-One每個 user thread 對一個 kernel thread並行度最佳（Windows、Linux 採用）
Many-to-Many多個 user thread 對較少或相等數量的 kernel thread彈性高

隱含執行緒（Implicit Threading）

  • Thread pool：預先建立好 thread 等待工作，省去建立成本。
  • Fork-Join：任務切開（fork）後，再合併結果（join）。
  • OpenMP：C／C++ 的編譯器指示詞，標記平行區域。
  • Grand Central Dispatch（GCD）：Apple 以 dispatch queue 管理任務。

另外，Thread-Local Storage（TLS）是每個 Thread 專屬的資料。

程式或範例

用兩個 Thread 分別計算 1～50 與 51～100 的總和，再由主執行緒加總。編譯時要加 -pthread。

/* 編譯：gcc sum.c -o sum -pthread */
#include <stdio.h>
#include <pthread.h>

static long partial[2];   /* 每個 thread 寫入自己的位置，不會互相干擾 */

void *worker(void *arg) {
    int id = *(int *)arg;
    int start = id * 50 + 1;
    int end = start + 49;
    long sum = 0;

    for (int i = start; i <= end; i++) {
        sum += i;
    }
    partial[id] = sum;
    return NULL;
}

int main(void) {
    pthread_t tid[2];
    int ids[2] = {0, 1};

    for (int i = 0; i < 2; i++) {
        pthread_create(&tid[i], NULL, worker, &ids[i]);
    }
    for (int i = 0; i < 2; i++) {
        pthread_join(tid[i], NULL);   /* 等 thread 結束 */
    }
    printf("total = %ld\n", partial[0] + partial[1]);
    return 0;
}

預期輸出：

total = 5050

Amdahl 計算範例：程式有 75% 可平行化（S = 0.25），在 2 個核心上：

Speedup = 1 / (0.25 + 0.75 / 2)
        = 1 / 0.625
        = 1.6 倍

考試重點

  • Thread 共享哪些資源、各自擁有哪些資源。
  • 多執行緒的四大好處（Responsiveness、Resource sharing、Economy、Scalability）。
  • 並行與平行的差別：單核心只能並行，不能平行。
  • Amdahl 定律的計算，以及加速上限 1 / S。
  • 三種多執行緒模型的差異，尤其 Many-to-One 一個阻塞全部阻塞。

常見錯誤

  • 把並行當成平行。單核心靠快速切換只是「並行」。
  • 以為 Thread 共用 Stack。實際上每個 Thread 有自己的 Stack 和暫存器。
  • Amdahl 定律把 S 與 1 - S 放反。S 是「循序」的比例。

練習題

題目 1：S = 0.25、N = 4，加速比上限是多少？

Speedup = 1 / (0.25 + 0.75 / 4) = 1 / 0.4375 ≈ 2.29 倍。

題目 2：N 趨近無限大時，S = 0.2 的程式最多加速幾倍？

上限為 1 / S = 1 / 0.2 = 5 倍。

題目 3：為什麼 Many-to-One 模型無法善用多核心？

所有 user thread 都對應到同一個 kernel thread，一次只能有一個在核心上執行；而且其中一個阻塞時，整個 Process 都會被阻塞。
